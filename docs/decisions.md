## D-001 项目拆分为「博客」与「个人文件系统」两个独立项目

- **日期**：2026-11-02
- **状态**：✅ 已确认
- **背景**：用户希望一个网站同时承载博客和网盘。
- **决策**：拆成两个独立项目，各自独立仓库、独立部署，通过子域名或接口对接。
- **理由**：两者性质不同——博客是静态内容，文件系统是动态服务；文件系统复杂度约高出一个数量级（涉及大文件分片上传、下载鉴权、目录树元数据）。合并会使学习与心智负担翻倍。
- **代价**：用户以后需维护两个项目，并补学后端。

- **日期**：2026-11-02
- **状态**：✅ 已确认（暂缓开发）

## 附一：三种渲染方式

| 方式 | HTML 生成时机 | 特点 |
|---|---|---|
| 静态生成 SSG | 构建时一次性生成 | 快、便宜、可 CDN；内容变动需重新构建 |
| 服务端渲染 SSR | 每次请求现场拼装 | 内容实时；需服务器常驻 |
| 客户端渲染 CSR | 在浏览器内用 JS 渲染 | 首屏慢；交互灵活 |

## 附二：三个框架对比

| 框架 | 定位 | 优点 | 缺点 |
|---|---|---|---|
| Next.js (React) | 全栈全能 | 真正一体化，博客与接口同项目；生态最强 | 概念多（App Router / Server Component / Route Handler），需清楚每段代码的运行位置 |
| Astro | 内容优先 | 纯静态输出、性能最佳、学习曲线平缓 | 动态功能弱，需另起后端 |
| Nuxt 3 (Vue) | 全栈，对标 Next.js | 能力与 Next.js 相当 | 中文生态资料相对少 |

## 附三：四种文件存储方案对比

| 方案 | 本质 | 关键差别 |
|---|---|---|
| Cloudflare R2 | 对象存储 | 10GB 免费，下载不收流量费 |
| AWS S3 | 对象存储（行业标准） | 工具链最全，但按流量收费，出站较贵 |
| Supabase Storage | 存储 + 数据库 + 登录打包 | 学生最省事，鉴权免写 |
| 自建 MinIO | 自托管对象存储 | 等于自造 S3，运维自理；是从云存储过渡到 NAS 的跳板 |

> 关键认知：云存储贵的通常不是「存」而是「取」。存 1TB 可能几十元，下载 1TB 流量在 S3 上可能收数百元。

## 附四：基础概念——对象存储 ≠ 文件系统

- 对象存储是扁平结构，只有「key → 内容」映射，没有真实目录；界面上看到的文件夹是模拟的，移动目录相当于批量修改 key。
- 文件系统有真实目录树、inode、权限、文件锁、追加写能力。
- 网页版网盘的做法：数据库存目录树元数据 + 对象存储存内容，两者配合。
